# evidence_timing

정보처리학회 ACK 2026 논문 "미래 상태 예측 기반 V2X 위치 위조의 증거는 언제 드러나는가" 실험.

이 폴더의 `v2x_evidence_timing.py` 는 처음 작성한 원본 스크립트를 VeReMi NextGen(InTAS highway_2) 실데이터에 맞춰
고친 것이다. 고친 곳은 아래 "원본에서 바꾼 것"에 전부 적어 두었다.

## 재현 방법

```bash
# 1) 이중 zip 으로 배포된 원본을 veh_*.json 폴더로 푼다 (한 번만)
python evidence_timing/prepare_data.py

# 2) 실험 실행 (약 4분)
D=data/raw/veremi_nextgen/extracted/InTAS_highway_2
python evidence_timing/v2x_evidence_timing.py \
    --test  $D/Test \
    --val   $D/Validation \
    --out   evidence_timing/results
```

`.venv` (numpy/pandas/scipy/matplotlib) 로 실행한다. `shapely` 는 필요 없다.

## 원본에서 바꾼 것

### 1. sendTime 단위 (`--time-unit`, 기본 auto) — 안 고치면 결과가 전부 틀린다

배포본의 `sendTime` 은 OMNeT++ simtime 을 **나노초 정수 문자열**로 적어 둔 것이다
(`"7454118965202"`). 원본은 `float(m["sendTime"])` 로 그대로 읽어 초로 취급하므로
메시지 간격이 1초가 아니라 1e9초가 되어 속도·가속도·저크가 전부 무의미해진다.
메시지 간격 중앙값이 0.02~5초 구간에 들어오는 배율을 자동으로 골라 나눈다.

### 2. 결측 구간이 있는 송신자 제외 (`--max-dt-jitter`, 기본 0.2초) — sigma 가 767배 틀어진다

수신 차량이 통신 범위를 벗어나면 비콘이 수십 초씩(최대 69초) 끊긴다. 그 구간에서는
식 (1)의 `|Δp|`(직선 거리)가 `v̄·Δt`(곡선 경로 길이)보다 훨씬 짧아 잔차 r 이 수백 m 까지
벌어진다. 전체 간격 중 이런 결측은 0.9% 뿐이지만, 분산 통계인 sigma 는 완전히 망가진다.

| | 정상 sigma | order=1 사건 탐지 |
|---|---|---|
| 필터 없음 (원본) | **161.2 m** | **2 / 247** |
| 필터 적용 | **0.21 m** | **97 / 97** |

sigma 가 161 m 이면 `D²/(2σ²) ≥ ln(1/α)` 문턱을 사실상 못 넘어 k\* 와 최적 탐지기 지연이
거의 전부 NaN 이 된다. `results_nojitterfilter/` 가 그 상태의 결과다.

이 기준(간격이 중앙값에서 0.2초 넘게 벗어나면 제외)은 새로 만든 것이 아니라
`timewarp/common.py` 의 `load_benign()` 이 이미 쓰고 있던 것과 같다. 실제로 필터 적용 후
test 송신자 수가 **191명**으로, `timewarp` 쪽 로그의 `test benign 송신자 191명` 과 정확히
일치한다.

## 실행 결과 요약 (InTAS highway_2, test 191명 / val 66명, 급감속 사건 1305건)

정상 잔차 sigma = 0.21 m (c=1.0), 이동평균 탐지기 임계값 eta = 0.611, 실측 오탐률 0.71%.

- **H1 지지.** 측정 불일치 D 와 식 (2) 예측의 상관이 1/2/3차에서 0.968 / 0.918 / 0.927.
  순항 중에는 `|D|/sigma` 중앙값이 0.47(1차)로 묻히고, 가감속 구간에서 13.9 까지 올라간다.
  즉 불일치는 예측 차수가 따라가지 못하는 **가감속 변화**에서 생긴다.
- **H2 부분 지지.** 1차 공격자의 최적 탐지기 지연이 `tau*jerk` 에 대해 기울기 **-0.654**
  (이론값 -2/3 = -0.667, 기준 ±0.2) 로 잘 맞고, 식 (4) 예측과의 오차 중앙값도 0.29초
  (기준 1초 이하) 다. 2차·3차는 각각 -1.53, -2.73 으로 차수에 따라 가팔라진다.
  다만 **잡음 배율 c 기울기는 0.218 로 기준(+2/3 ±0.2)을 벗어난다** — 아래 "남은 문제" 참고.
- **H3 지지.** 실제 탐지기 지연이 최적 탐지기보다 1차 1.53초 vs 0.81초, 2차 1.35초 vs
  0.52초, 3차 3.76초 vs 1.35초로 항상 길다(사건 단위로도 98~100%가 그렇다).
  그 격차(gap) 중 이동평균이 만드는 몫은 1차에서 0.72-0.21 = 0.51초로 대부분이다.

## 남은 문제 (원고에 반영하거나 추가 확인이 필요한 것)

1. **잡음 배율 기울기가 이론과 안 맞는다 (0.218 vs +2/3).**
   원인은 c 를 키워도 sigma 가 비례해 커지지 않기 때문이다
   (c=0.5/1/2 에서 sigma = 0.173 / 0.210 / 0.317, 즉 sigma ∝ c^0.44).
   잔차에 c 와 무관한 성분(스플라인 평활 오차, 경로 보간 오차)이 깔려 있어서,
   데이터셋의 측위 잡음만 배율로 키우는 방식으로는 이론이 가정한 sigma ∝ c 를 만들지 못한다.
   원고에서 이 실험을 "측정 잡음의 영향" 근거로 쓰려면 잔차의 c-무관 성분을 분리하거나,
   합성 데이터(`--synthetic`)에서 따로 검증하는 편이 안전하다.

2. **감속 시작 시점에 이미 경보 상태인 사건이 1305건 중 396건(30%)** 이라 분석에서 빠졌다.
   순항 중에도 경보가 켜진다는 뜻이므로, 탐지기 임계값이나 사건 정의를 다시 볼 필요가 있다.

3. **정상 잔차의 lag-1 자기상관이 c=0.5 에서 0.40** 이다. 식 (3)은 독립을 가정하므로
   이 조건에서는 근사가 약해진다 (c=1.0 에서는 0.18, c=2.0 에서는 -0.08).

4. 이 데이터셋에는 `AGGRESSIVE` / `NORMAL` 두 운전자 유형만 있고 `CAUTIOUS` 는
   급감속 사건 기준을 넘긴 경우가 없어, 유형별 비교는 두 값(0.875초 / 0.900초)뿐이다.

5. `k*` 와 최적 탐지기 지연의 차이 중앙값이 세 차수 모두 정확히 0.000초로 나오는데,
   이는 비콘 주기가 1초라 둘이 같은 메시지에서 문턱을 넘으면 차이가 0으로 떨어지기 때문이다.
   "1초 미만까지 일치한다"는 근거로 쓰기에는 분해능이 부족하다.
